# Auto Buff local gameplay test — 2026-10-30

I ran Anomoly on a local vanilla Minecraft Java 26.3 multiplayer server. Server commands supplied items and read health, food, active effects, selected item, and inventory after client ticks. For these tests I enabled Auto Buff's Soup, Head, Gapple, Pot, Drink, Refill, and Auto Swap groups; the normal default enables only Pot and Refill.

| Case | Server observation |
| --- | --- |
| Refill and beneficial splash | A Strength splash potion placed in main inventory moved into an empty hotbar slot, was thrown, and gave the player Strength. The selected stone remained in slot 0. |
| Harmful control | A Poison splash potion stayed in inventory while the player retained only the earlier Strength effect. |
| Healing splash | At 6 health, a Healing splash potion was consumed and health rose to 10; the Poison potion remained untouched. |
| Drink | A regular Swiftness potion was consumed, added Speed, left a glass bottle, and restored the selected stone. |
| Golden apple | At low health, a golden apple was eaten and gave 4 absorption. After the synthetic use-key release was fixed, a later apple could be eaten after a Speed potion in the same session. |
| Full-hotbar Auto Swap | With all nine hotbar slots containing stone, a Speed potion in main inventory was temporarily swapped into the selected slot, drunk, then swapped back. The server showed all nine stone items still in the hotbar, a glass bottle in main inventory, Speed active, and stone selected. |
| Soup | A Hunger effect reduced food to 0. With health below the soup threshold and a mushroom stew in main inventory, Auto Buff consumed it, raised food to 6, dropped the empty bowl, and restored the selected stone from a full hotbar. Stock soup did not directly heal. |
| Custom edible head | A player head with 26.3 food and consumable components plus an Instant Health consume effect was used at low health. The server recorded health rising from 8 to 12 and the head disappearing from inventory. |

The first combined apple-to-potion run exposed a use key that stayed down after eating. I changed Auto Buff's injected key release to clear that state explicitly and repeated the sequence successfully. The same release fix was applied to Auto GApple. A final run with Kill Aura active still applied a Strength splash after the combat-pause integration was added, but the exact pause duration was not isolated by the server queries. Nearby-player splash protection, lingering potions, combat suppression, head cooldown, and third-party anticheats also need separate gameplay tests.
