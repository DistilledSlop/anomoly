# Surround gameplay test — 2026-10-30

Tested on a local vanilla Minecraft Java 26.3 server with PlayerA on a flat stone platform. Surround was the only enabled module. Placement used Minecraft's normal `MultiPlayerGameMode.useItemOn` prediction and interaction path. The server block states, player position, selected item, and inventory counts were read from its console.

| Probe | Server observation |
| --- | --- |
| Hotbar placement | With stone selected in slot 0 and eight obsidian in slot 1, all four blocks at `(5,100,4)`, `(6,100,5)`, `(5,100,6)`, and `(4,100,5)` became obsidian. Slot 0 still held stone; the obsidian count fell to four. |
| Collision guard | At `(5.8,100,5.3)`, the module placed two sides and skipped sides intersecting the player's collision box. After the player moved to `(5.5,100,5.5)`, it placed the remaining sides. |
| Repair | Removing the north side with a server command led to a new obsidian block there and reduced the hotbar count from four to three. |
| Offhand | After the hotbar obsidian was removed and two obsidian were put in the offhand, removing the east side led to a replacement block. |
| Center on enable | With the shell removed, PlayerA at `(5.8,100,5.3)`, and Surround toggled on, the server measured `(5.5,100,5.5)` and all four sides became obsidian. |

Centering only runs when the player is grounded and the destination is collision free. The normal server movement path accepted the centered position in this test. The module leaves blocks in place when disabled. The test does not establish compatibility with third-party anticheats or all protected building regions.
