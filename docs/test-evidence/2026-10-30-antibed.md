# Anti Bed gameplay test — 2026-10-30

Tested with Anomoly on a local vanilla Minecraft Java 26.3 server. PlayerC stood in survival at `(50.5,100,50.5)` on a flat stone floor, with stone selected in hotbar slot 0 and 64 string in slot 1. Anti Bed used its default cardinal coverage, line-of-sight check, and three-tick placement interval. The server console supplied block and inventory observations.

| Probe | Server observation |
| --- | --- |
| Default protection | Tripwire appeared at `(50,100,50)` and all four cardinal neighbors: `(50,100,49)`, `(51,100,50)`, `(50,100,51)`, and `(49,100,50)`. Stone remained selected. |
| Offhand repair | After clearing hotbar string, putting string in the offhand, and removing the east tripwire, Anti Bed replaced it. Stone remained selected. |
| No material | After clearing offhand string and removing the east tripwire again, the cell remained air. |
| Bed placement against string | PlayerC moved to `(47.5,100,50.5)`, faced east and down, selected a red bed, and right-clicked toward the protected west and center cells. Both tripwire blocks remained and the bed item remained selected. |
| Paired bed control | After clearing tripwire at `(49,100,50)` and `(50,100,50)`, the same right-click placed a red bed across those two cells and consumed the item. |

Minecraft 26.3 registers string as the tripwire block item. Its block has no collision but does not mark itself replaceable; bed placement requires both bed cells to be replaceable. The normal multiplayer bed interaction confirmed the denial on this server. This test ran in the Overworld, where beds can be placed safely. Nether and End bed explosions, diagonal coverage, moving-player behavior, protected regions, and third-party anticheat compatibility remain unverified.
