# Auto Bow gameplay test — 2026-10-30

I ran the 26.3 Fabric client against a local vanilla 26.3 multiplayer server in OpenGL/Xvfb. Auto Bow was enabled with `target_mobs=true` and default aim, charge, and interval settings. The client had no manual movement, use, or attack input after each server setup. The server placed the player at `(5.5, 100, 5.5)` facing south, with a stationary no-AI pig at `(5.5, 100, 21.5)` on a level stone platform. Stone was in the selected hotbar slot; the ranged weapon was in the next slot.

## Bow

The server gave the player a bow and 64 arrows. Auto Bow selected the bow, drew it for the default 20 ticks, aimed, and released. The server awarded **Take Aim** and recorded that the pig **was shot by Player956**. Afterward the server's `SelectedItem` query returned `minecraft:stone`.

## Crossbow

In a fresh setup with a crossbow and 64 arrows, Auto Bow selected the crossbow, charged and released it, then used the loaded crossbow to fire. The server awarded **Ol' Betsy** and recorded that the second pig **was shot by Player956**. `SelectedItem` again returned `minecraft:stone`.

## Trident

In a third setup with a trident and no arrows, Auto Bow selected, charged, and threw the trident. The server awarded **A Throwaway Joke**. The pig's server-reported health fell from its normal 10 to `2.0f` after one throw, and `SelectedItem` returned `minecraft:stone`. The [captured game frame](2026-10-30-autobow-trident.png) shows the pig with the trident embedded and the advancement message.

All three shots used `MultiPlayerGameMode.useItem` and `releaseUsingItem`, with vanilla draw durations. The configurable bow charge can release earlier for lower-powered shots; it does not accelerate the server's charge timer. Pre-charged crossbows, firework-loaded crossbows, moving targets, Riptide tridents, and anticheat compatibility were not established by this test. Riptide tridents are deliberately skipped because their use action launches the player rather than a trident projectile.
