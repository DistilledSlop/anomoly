# Auto Swim gameplay test — 2026-10-30

Tested Anomoly on a local vanilla Minecraft Java 26.3 server in a 20-block enclosed water tunnel. A temporary server predicate checked the player's `is_swimming` flag. Water Breathing kept the player safe during repeated runs. Auto Walk supplied the same forward input in both cases; F7 toggled Auto Swim and F8 toggled Auto Walk.

| Probe | Server observation |
| --- | --- |
| Forward control | With Auto Walk on and Auto Swim off, the player moved from X 1301.5 to X 1305.42. The server predicate reported `is_swimming=false`. |
| Auto Swim enabled | With Auto Swim on and the same forward input, the server predicate reported `is_swimming=true` shortly after the player was teleported back to X 1301.5. |
| Reset | Turning off Auto Walk and releasing forward input returned the server predicate to `is_swimming=false`; the later control began from that reset state. |

The test verifies the underwater forward case and the paired control on vanilla 26.3. Surface swimming, obstacle interactions, and third-party anticheats remain untested.
