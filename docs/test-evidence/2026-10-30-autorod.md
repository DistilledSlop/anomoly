# Auto Rod gameplay test — 2026-10-30

I ran the 26.3 Fabric client against a local vanilla 26.3 multiplayer server on a level stone platform. The player stood at `(5.5, 100, 5.5)` with stone selected and a new fishing rod in the next hotbar slot. A stationary, no-AI pig stood at `(5.5, 100, 11.5)`, six blocks ahead. Auto Rod was enabled with `target_mobs=true`; no manual use or attack input followed setup.

The first solver profile used launch speed 0.6 and rejected this target as unreachable. The decompiled 26.3 `FishingHook` constructor actually adds approximately 0.5 to the per-axis launch factor after the normalized 0.6 term. I corrected the hook profile to approximately 1.1 and kept the game's gravity-before-move, drag-after-move order: gravity 0.03 and drag 0.92 per tick. The same solver continues to use the unchanged update order for the existing arrow and throwable profiles.

With the corrected profile, Auto Rod selected the rod, aimed, cast, and reeled repeatedly. A server inventory query after the run showed rod damage **30**, while `SelectedItem` was `minecraft:stone`. The decompiled `FishingHook.retrieve` assigns five durability damage when a hooked living entity is reeled in; a ground hit assigns two, and an unhooked reel assigns zero. Damage 30 from a new rod is consistent with six entity-hook reels. The pig remained at its initial location because it had NoAI, so this test does not measure knockback distance.

I then pressed the End panic key. The saved Auto Rod state became disabled; the server reported stone selected and no remaining `minecraft:fishing_bobber` entity. This verifies cleanup after disabling as well as the automatic cycle. The local server had no anticheat plugin, and moving-player tracking was not tested.
