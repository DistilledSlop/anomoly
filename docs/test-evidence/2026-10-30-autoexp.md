# Auto Exp gameplay test — 2026-10-30

I ran the 26.3 Fabric client against a local vanilla 26.3 multiplayer server on a level stone platform. Auto Exp was enabled with its default 85% durability threshold and eight-tick bottle interval. No use or attack input was sent after setup. The module throws through the ordinary item interaction API with a downward use-packet pitch, then restores the view and hotbar selection.

## Armor repair

The server equipped Player389 with an iron helmet carrying Mending I and damage 100, gave the player stone in the selected slot and 32 experience bottles in the next hotbar slot. The server then reported helmet damage **24** and **26** bottles remaining: six bottles had been selected and thrown automatically. `SelectedItem` was stone. A later query reported the same damage and bottle count, confirming that Auto Exp stopped after passing the 85% remaining-durability threshold. An iron helmet has 165 durability in this version; damage 24 leaves about 85.5%.

As a negative control, I replaced the helmet with a damage-100 iron helmet without Mending. After five seconds the server still reported 26 bottles and damage 100. The module did not throw bottles for equipment that cannot be repaired by Mending.

## Held-tool repair

I cleared the inventory, put a damage-100 Mending I iron pickaxe in the main hand, and placed 16 experience bottles in the offhand. The module used the offhand bottles while keeping the pickaxe held. The server then reported pickaxe damage **20** and **10** bottles remaining, so six bottles repaired the tool. For a tool in the main hand, bottles must be in the offhand; selecting a hotbar bottle would unequip the tool and make it ineligible for Mending.

The local server had no anticheat plugin. Repair rate depends on the experience generated by each bottle and on which eligible Mending item receives each orb. This test does not establish compatibility with anticheats.
