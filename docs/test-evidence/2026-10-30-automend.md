# Auto Mend gameplay test — 2026-10-30

Tested Anomoly on a local vanilla Minecraft Java 26.3 server. F7 toggled Auto Mend. The player held damaged iron tools with Mending, and server commands summoned real experience orbs and queried inventory items, damage components, offhand contents, and module state. The selected hotbar slot stayed at 0 throughout.

| Probe | Server observation |
| --- | --- |
| Occupied offhand guard | With the default `force=false`, a totem in the offhand stayed there while damaged Mending tools remained in inventory. The module stayed enabled and waited. |
| Two-tool repair | With the offhand empty, Auto Mend moved a damaged iron shovel from inventory into the offhand. A 50-XP orb repaired its 80 damage, and the module stored the repaired shovel while moving a 100-damage Mending pickaxe into the offhand. A 60-XP orb repaired the pickaxe. The module stored it in an empty inventory slot, left the offhand empty, and disabled itself. Both tools retained their Mending enchantment and had no damage component. |
| Force, blacklist, and restoration | With `force=true`, a totem in the offhand, and `minecraft:iron_pickaxe` blacklisted, the module chose the damaged shovel, kept the totem in the shovel's original slot during repair, and left the damaged pickaxe untouched. After another 50-XP orb repaired the shovel, it restored the totem to the offhand, stored the repaired shovel, and disabled itself. |

The module uses ordinary inventory clicks and does not move items while another menu is open or Auto Totem is enabled. Full inventories, manual inventory changes during a repair cycle, other Mending items, and third-party anticheats remain untested.
